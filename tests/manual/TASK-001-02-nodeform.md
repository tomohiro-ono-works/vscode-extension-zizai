# TASK-001-02 NodeFormのVS Code適合確認（試作）

対象：VS Code 1.142.0／Windows、検証拡張0.0.1。Kiroは対象外。Jupyter拡張とPythonカーネルは不要。製品のフォーム配置を決めるテストではなく、検証専用Webviewタブで部品の読込・CSP・テーマ・イベント・実ファイル選択を確かめる。

## 起動

1. 最新の `spike/task-001-01-notebook-ui` を取得し、リポジトリ直下をVS Codeで開く。前の開発用ウィンドウは閉じる。
2. F5の設定で **TASK-001-02: NodeForm Reuse (PROTOTYPE)** を選ぶ。Node.js 20以降とGitがPATHに必要。npm installは不要。
3. 初回は固定commitの上流JS／CSS／LICENSEをGitHubから取得し、hash照合後、検証用の1行patchとテーマCSSを組み合わせて生成する。元LICENSEとZizai向け許諾記録も生成先へ同梱する。生成物・キャッシュはGit無視のdist/内。以降は照合済みキャッシュを再利用する。
4. 開いた別ウィンドウでCtrl+Shift+P → **Zizai Probe: Open NodeForm Reuse Test**。タイトルに「試作」とある別タブに入力フォームが表示される。

初回のGitHub取得が難しい場合は、[上流の取得手順](../nodeform-reuse/README.md#再現) で固定commitを取得し、ルートで `node tests/nodeform-reuse/prepare-webview.mjs ../zizai-form-check` を実行する。その後F5を押すとキャッシュから準備する。上流の改変版や改行変換されたファイルはhash不一致で停止するため、cloneはcore.autocrlf=falseで行う。

## 確認する操作

実データを入力せず、ファイルは検証用の空ファイルやフォルダーを使う。選択した内容の読み取り・Python実行・Notebook変更は行わない。

| ID | 操作 | 期待結果 |
| --- | --- | --- |
| F1 | 起動後のフォームを見る | 入力欄とボタンが表示される。真っ白な画面やCSP／スクリプト例外が出ない |
| F2 | 空で「入力検証」→名前を入力→追加項目をshowへ変更→追加項目も入力して検証 | 必須エラーが項目下へ出る。showで追加項目が表示され、必要な入力が揃うと検証OK。hideでは非表示項目は検証対象外 |
| F3 | 候補付き入力へ文字を数回入力し、候補を選ぶ。外をクリックして閉じ、「フォームを作り直す」 | 候補選択と開閉ができ、再作成で初期状態に戻る。リスナー残留0件はクラウドで確認済みなので、実機では操作の反応を確認する |
| F4 | ファイルとフォルダーをそれぞれ選択し、続けてキャンセルも試す | OSダイアログの結果が該当欄へ入り、キャンセルは元の値を維持。選択ボタンが「選択中」のまま残らない |
| F5 | VS Codeの「基本設定: 配色テーマ」でLight／Dark／High Contrastのテーマに切り替える | 入力・候補・ボタン・エラー・フォーカス枠が読める。暗いテーマで入力欄だけ白くならず、フォーム外へCSSが広がらない。確認したテーマ名を記録 |
| F6 | コマンドをもう一度実行して2つ目のフォームタブを開き、別の名前を入力する | 一方の値や再作成操作が他方へ反映されない |

「環境を報告」ボタンはIDE／Host Node／OS／試作版／上流commit／patchとCSSのhashを表示する。フォーム値や選択したパスは報告に含めない。返してほしい情報は **F1〜F6の結果、確認したテーマ名、環境報告JSON**。表示に問題がある場合だけ画面かエラーログを付ける。
