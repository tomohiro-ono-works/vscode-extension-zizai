# サイドバーとHostのAPI・結合確認ケース

担当：[TASK-001-05](https://github.com/tomohiro-ono-works/vscode-extension-zizai/issues/12)。[サイドバー設計](../../docs/features/notebook-sidebar.md)と[単体ケース](../unit/sidebar-cases.md)に基づく再利用する定義で、実行スクリプト・実施結果ではない。TASK-002の製品API・診断コードは編集しない。

## 共通の分類・担当・実行条件

- 全Kケースの分類は**API・結合テスト**、準備・実行・分析・記録はエージェント。正式なUI／Host境界・Notebook API・標準コマンドを通し、状態・イベント・保存結果を照合する。VS Codeを起動する検査でも、画面への実入力を通さなければ手動UI検証・UI自動テストにはしない。
- 対象版は試験する製品commitと、その版に接続した契約・Hostのcommitを固定する。OS・VS Code・拡張・Nodeの実際の版を記録。K06ではJupyter・Python拡張・カーネルの実際の版も記録する。現時点で製品入口・runnerは未確定、全件未実施。
- 必須前提は001-04の対象部分、005の正式通信／metadata・validator、002のHost対象部分、006-02の再現可能な検査入口。相手Task全体の完了は求めない。API署名・復旧方式・コマンド名をこの定義から先取りしない。
- 架空Notebook N・M、処理セルA・B、通常Python・初期化セルを使う。標準nbformatを満たすfixtureと正式な製品定義を受領して用意する。表示番号を対象識別に使わない。schema不正の既存診断fixtureの結果を製品の識別保証にしない。
- 失敗・遅延応答の制御点は、正式アダプターと許可された試験境界で確定する。モック／注入箇所を記録し、UI・OS・実セル保存の未確認部分を明示。製品へ未承認の試験専用APIを追加しない。ユーザーへターミナル・ログ整理を依頼しない。

## 実行と記録

K01の保存・復元と関連する対象境界は[前後比較の詳細条件](sidebar-selection-state-cases.md)で具体化する。Hostへの下書き反映・標準保存・再オープンを別に観測し、対象変更とアクション変更を混同しない。詳細条件はKケースの内訳で、実施済み件数には加算しない。

エージェントが実在するrunner・コマンド・対象版を確認してIssue #12へ記録し、assertionと実セル・保存結果を読んで判定する。終了コード0や起動ログだけでは合格にしない。API・自動・手動UIを別の結果として扱い、未実施／不合格／合格／対象外（理由付き）と観測限界を記録する。

画面の入力経路は[手動UIケースM01〜M13](../manual/TASK-001-sidebar.md)へ渡す。UI自動化が必要ならPlaywrightの実クリック・キー入力を使う範囲・開始方法・担当を先に合意する。APIケースをUI自動化したと呼び替えない。
