# K01詳細：セル選択・下書き保存・復元の前後比較

[API・結合ケースK01](sidebar-cases.md)と関連するK03〜K05を、前後の観測対象まで具体化する。[要件と責務](../../docs/designs/notebook-sidebar-requirements-review.md)を基準とし、正式キー・要求名・試験APIをここで確定しない。各条件は再利用するテスト定義で、実行コード・実施結果ではない。

## 共通の条件

- 分類はAPI・結合テスト、担当はエージェント。正式Host境界・Notebook API・標準コマンド・保存結果を観測する。画面への実入力を通さない検査を、手動UIまたはUI自動の合格にしない。
- 対象commit、契約・Hostの版、OS・VS Code・Nodeと試験runnerの実版は実行前に固定し記録する。開始条件は001-04の対象部分、正式な対象／下書き／保存・復元契約、Host境界とrunner。現在は未充足で全条件未実施。
- 製品の正式な定義に適合する、外部接続・認証・Python実行を必要としない試験用入力を使う。以下のC・D・Sは比較用の呼称で、metadataのキーやフォームschemaではない。
- NのセルAに旧確定値C-A、下書きなし、source S-Aを用意し、BはC-B／S-Bを持つ。下書きD-AとD-Bは互いと確定値から区別できる架空値。別Notebook Mも同じファイル名・セル位置を持つが別の架空値を使う。正式な標準cell.idを備えたNotebookと、拡張管理外の架空sentinelを用意する。
- エージェントが専用試験環境の標準Auto Saveを無効にし、初期状態を標準保存する。ユーザーの通常ワークスペース・グローバル設定は変更しない。Auto Save有効の別条件を確認する場合は分けて記録し、標準の自動保存を「拡張独自の自動保存」と誤認しない。
- 各行は独立に初期化する。処理前、Host応答後、標準保存後、再オープン後を区別し、UI入力・Host下書き・確定値・source・保存ファイル・所有外metadata・対象を比較する。値本文・選択パス・sourceは診断ログへ出さず、架空fixtureの期待値とassertionの対応で記録する。

## 判定と境界

上記はK01と関連する境界の詳細条件であり、新たな8件の製品テスト合格を示さない。各行に対象版・操作／コマンド・実結果・モック／注入箇所・未確認を記録して判定する。K03の移動・複製・Undo、K04のファイル選択、K06の現在設定に対応する実行成功、K07の不正通知はそれぞれのケースを維持する。

手動UIの実操作は[M01〜M13](../manual/TASK-001-sidebar.md)でユーザーが担当し、エージェントが準備・証跡採取・分析・記録する。準備完了報告と開始合図の前に実行しない。PlaywrightによるUI自動へ変更する場合も範囲・開始方法・担当の事前合意が必要。単体注入やAPI成功を画面入力経路の証明へ振り替えない。
