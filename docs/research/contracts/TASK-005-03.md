## 値とPython sourceの対応案

以下は共通境界への提案。metadataの正式キーやJSON Schemaではない。部品から届いた値をそのままPython式へ連結せず、アクション定義にある入力の種類に従ってHostで検証・変換する。

| 入力の種類 | sourceへの対応候補 | 区別するもの・残る条件 |
| --- | --- | --- |
| 文字列・SQL・scriptの本文 | 引用符・改行・バックスラッシュを保つPython文字列リテラル | 文字列を通常の生成処理でPython式として評価しない。Pythonコネクタがscriptをどう扱うかは個別の判断 |
| path | カーネルから参照できるpath文字列として表現 | Windowsのバックスラッシュも保存。末尾バックスラッシュを持てないraw文字列の機械的利用は避ける候補。HostのURIとカーネルのpathは同一とは限らない |
| bool・数値 | True／False、型と範囲を検証した数値リテラル | Falseと0を未設定にしない。有限値、整数・小数、JavaScriptで精度を失う大きな整数の表現を定義する必要がある |
| 配列・辞書 | 要素・キーの型を検証し、Pythonのlist／dictとして表現 | NodeFormの特殊部品が返すJSON文字列と、既に構造化された値を区別する。全ての文字列をJSONとして解釈しない |
| null／任意値の欠落 | 明示Noneと、引数自体を省略する場合を区別 | 欠落時の初期値をUI・Host・Pythonで一致させる。空文字も別の値として扱う |
| 入力表などの変数参照 | 例のdf_salesなら、引用符なしの単一変数名として生成 | UI／metadataには参照名だけを保持。実オブジェクトはカーネル内。存在・型の最終確認はPython側で行い、Hostから裏側で評価しない |
| 出力の変数名 | 代入が必要なら検証した単一名を使う | 自動名・利用者指定・衝突・既存値の上書きは未決。新しいフォーム欄の追加は今回決めない |
| 非表示・未知の項目 | 有効なアクション入力だけを引数へ渡す候補 | 非表示値を保存するか、実行引数へ渡すかは別。未知キーを任意のメソッド／引数へ転送しない |

単一変数名は、最初はASCIIの英字・数字・アンダースコアかつ先頭数字不可、Python予約語不可とする案を比較対象にする。Unicode識別子を認める案もあり、正式な制限ではない。df.ilocや関数呼出し等の式を認めるかも未決だが、最小案では単一名に限定する。自由なPythonは標準コード欄で書ける既存方針を維持する。

呼出し先のmodule・class・methodはアクション定義との対応で管理する候補。利用者のフォーム値をそのままimport名や呼出し先へ使わない。JSONのtrue／false／nullとPythonのTrue／False／Noneは異なるため、JSON文字列をPython sourceとして直接使う方式にしない。変換器は今回実装していない。

## 未設定・下書き・確定の整理

- 選択時：以前のアクションの下書き・確定値を破棄し、新アクションの初期値と未設定状態からsourceを生成する既存方針を継承する。
- 編集中：下書きだけを更新し、現在の確定済みsourceを維持する。
- 確定NG：入力欄へ検証結果を返し、確定済み設定とsourceを変更しない。セル更新の原子性・失敗応答はTASK-005-02／TASK-002-02で定義する。
- 確定OK：型・必須条件を満たした値と対象アクションからHostがsourceを生成する。生成だけではPythonを実行しない。

| 未設定のsource案 | 標準実行したとき | 判断点 |
| --- | --- | --- |
| U1：説明コメント＋明示的なValueError（推奨候補） | 未設定と分かるPythonエラー。標準の「すべて実行」もそのセルで停止する | 設定漏れを明確にできるが、後続セルも止まる影響がある |
| U2：説明コメントのみ | 何も処理せず、標準実行は次へ進む | 未設定でもエラーが出ない。業務処理を実行した成功と区別する必要がある |
| U3：有効な初期値だけで業務呼出しを生成 | 手動の標準実行時に初期値で実処理する | 必須path・SQL・project等の妥当な値を保証できないアクションがある。仮のIDや空欄を有効とみなさない |

U1／U2について利用者へ動作を確認中。回答前に採用しない。U3を全アクションへ一律適用しない。未設定のsource生成と、標準実行を拡張側で禁止する仕組みは別であり、独自の実行制御は追加しない。

### C. DraftValuesとBoundValues

フォーム部品のgetParams結果をそのまま保存schemaやPython引数にはしない。保存する途中入力と、検証済みの生成引数を分ける。

| 型候補 | 表現・規則 |
| --- | --- |
| `DraftValues` | `{fieldId: DraftValue}`。text/path/number/variableの入力途中は `{kind:"text",text:"..."}`。bool・選択値・構造化部品は `{kind:"json",value: JSON値}`。明示的な未設定は `{kind:"unset"}`。numberの `"-"` や未完成の変数名も文字列として保存できる。欠落は未入力、空文字とnullを同一にしない |
| `BoundValues` | `{fieldId: BoundValue}`。検証済み・有効な欄だけ。任意引数の省略はキー欠落。必須値欠落は確定NG |
| 通常値 | `{kind:"literal",value: JSON値}`。string／bool／null／有限数／list／string-key object。False・0・空配列は値。Noneへ渡すのはnullable欄の明示nullだけ |
| 任意精度整数 | `{kind:"integer",decimal:"9007199254740993"}`。正規化した十進文字列をPythonのint literalへ。JSON numberを経由して精度を失わせない |
| カーネル変数参照 | `{kind:"variable",name:"df_sales"}`。文字列literalとは別。単一識別子だけを生成し、存在・実型はカーネル実行時に確認 |

DraftValueのkindやJSON構造自体が不正なら通信入力不正として拒否する。欄の意味的検証は確定時に行い、不完全な値を保存不能にしない。nullable欄の明示Noneは `{kind:"json",value:null}` で表し、空textや欠落から推測しない。確定時にはactiveな全欄を検証し、初期値も同じ規則で正規化する。defaultは未編集の初期フォームを構成するときだけ適用し、解決済みの値をcommittedとsourceへ明示する。利用者が任意欄を未設定に戻した後の欠落へ、defaultを再注入しない。非表示欄のrequiredは適用しない。

#### 初期値・未設定・値の正規化表

再開・確定時に値を組み立てる順序を次のように具体化する。draftがある場合は全体置換の値として扱い、欠落欄をcommittedやdefaultで穴埋めしない。draft=nullのときだけcommitted、両方nullなら初期defaultを使う。これにより、任意引数の明示的な省略と、未編集の初期値を区別する。

| 入力候補 | 下書きでの扱い | 確定・生成結果 |
| --- | --- | --- |
| `{kind:"unset"}` または全体DraftValues内のキー欠落 | 未設定として保持。unsetにtext／value等の追加キーを認めない | requiredなら項目エラー、任意なら引数省略。defaultは再適用しない |
| `{kind:"text",text:""}` | 空文字入力として保持 | stringはminLength等に従う。path／variableは不正。空文字をNoneや省略へ変換しない |
| `{kind:"json",value:null}` | 明示null | nullableならliteral None、非nullableなら項目エラー。requiredとnullableは独立 |
| `{kind:"text",text:"00042"}` | 入力表記をそのまま保持 | integer欄なら42へ正規化。文字列欄ならそのままstring。先頭／末尾の空白を数値として勝手に除去しない |
| `{kind:"text",text:"-0"}` | 入力表記を保持 | integerは0、numberは数値変換の結果。string／pathの内容は正規化しない |
| `{kind:"json",value:false}` | boolとして保持 | boolean欄だけにFalse。number／integerの0と同一視しない |
| `{kind:"text",text:"9007199254740993"}` | 大きい整数もtext | integer欄ならinteger decimal表現。numberへの暗黙変換は拒否 |
| `{kind:"text",text:"df_sales"}` | 参照名または通常text | variable欄だけName参照、string欄ならliteral文字列。文字列の見た目で判別しない |

`DraftValue` にunsetを加えるのは「UI部品の空値を自動的に省略」とするためではない。adapterは初期値／入力／未設定を明示的に区別し、部品が表現できない場合は適合上の不足として扱う。新たなフォーム操作を製品実装へ追加する判断は001との照合後。完全なDraftValues内の欠落だけでも省略を表現できる。

field.default候補はDraftValue形式とし、unsetはdefaultとして許さない。定義収集時に型・範囲・nullableとの整合を検証してから初期表示へ使う。requiredは値の存在条件で、空stringの禁止はminLengthへ明記する。path／variableの空文字と不正構文は型条件で拒否する。一般の文字列・SQL・pathの空白、Unicode正規化、改行は入力どおり保持し、trimや絶対pathへの変換を共通処理に埋め込まない。

array／objectの通常literalに含まれる整数も安全整数域に制限する。任意精度integerのwrapperをJSON構造内の任意位置へ暗黙展開しない。入れ子の大きい整数が必要な欄は専用の型定義を004と合わせて追加するまで確定NGとする。metadata読込後だけでは、JSON number化の前に失われた精度を復元できないため、UIのadapter時点から数値を検査する。

単一識別子の案は `[A-Za-z_][A-Za-z0-9_]*`、Python予約語を除く。`None`／`True`／`False`も不可。`df.iloc`、添字、関数呼出し、複数文、Unicode識別子はフォーム変数参照には初回で認めない。Unicodeの文字列データは保持する。HostはPythonを呼び出して変数候補や型を調べない。

数値欄はJSON boolとnumberを区別する。通常整数はJavaScript安全整数域のみ、範囲外はinteger decimal表現。整数textは十進だけを許し、`+`・先頭ゼロ等は正規化、範囲・桁数は欄定義へ。floatは有限・欄の範囲内、NaN／Infinityは不可。自由なPython式・複素数・Decimalを初回の汎用値として追加しない。

### D. ActionDefinitionの契約案と部品変換

`ActionDefinition` の必須は `schemaVersion, connectorId, actionId, definitionVersion, fields, python`。定義は製品へ同梱した信頼できる正本から読む。Notebook metadataやUIからmodule／method／クラス／任意テンプレートを受け取らない。

| 定義欄 | 内容候補 |
| --- | --- |
| `fields[].fieldId` | アクション内で一意の保存キー。Python引数名と同じとは限らず、改名時は明示的な移行を要する |
| `labelKey`・`descriptionKey` | 表示文キー。生成引数には渡さない |
| `valueType` | `string \| path \| boolean \| integer \| number \| enum \| array \| object \| variable`。nullable／required／default／範囲、array item／object property schemaを型に応じて持つ |
| `visibleWhen` | 省略なら表示。指定は `{fieldId,equals: JSON primitive}` の単純な等値条件候補。参照先はenum／boolean等の制御欄。未設定は不一致、循環参照は定義不正。任意JS式は不可 |
| `inactivePolicy` | 初回は `preserveDraftOmitArgument` 固定。非表示値は同じアクションの下書きに保持、確定引数・BoundValuesには入れない。再表示時に下書き値を復元。アクション変更時には他の旧値と一緒に破棄 |
| `picker` | path欄の `file \| directory` と定義済みfilter。Hostが読む許可条件。UIはOS APIや任意commandを持たない |
| `python` | `module, className, instanceName, method, arguments, result`。argumentsは順序付き `{fieldId,keyword}` 配列。1欄から任意名のkwargsを展開しない |
| `python.result` | `display` または `none`。displayは自動結果名へ代入して最後の式に置く。noneは呼出しだけ。戻り型・例外の意味は004個別仕様へ対応付ける |

`definitionVersion` はアクションごとの正の整数で、値解釈・default・シグネチャなど保存済み値の意味が変わる更新で増やす。ラベルだけの変更とは分ける。未知版の値を最新定義で解釈して再生成しない。既知版の移行も、005-04で変換と値保持をレビューしてから提供する。

1欄だけに縮めたC01の構造説明例。これは製品の完全なCSV定義ではなく、encoding等を含む完成版は004との照合後に作る。

```json
{
  "schemaVersion": 1,
  "connectorId": "csv",
  "actionId": "read_csv",
  "definitionVersion": 1,
  "fields": [{
    "fieldId": "file_path", "labelKey": "csv.filePath",
    "valueType": "path", "required": true, "nullable": false,
    "inactivePolicy": "preserveDraftOmitArgument",
    "picker": {"kind": "file", "filters": {"CSV": ["csv"]}}
  }],
  "python": {
    "module": "zizai.connectors.csv", "className": "CsvConnector",
    "instanceName": "zizai_csv", "method": "read_csv",
    "arguments": [{"fieldId": "file_path", "keyword": "file_path"}],
    "result": "display"
  }
}
```

変換の経路は **ActionDefinition → UI adapter → DraftValues → Host検証／正規化 → BoundValues → Python生成**。NodeFormのfield名／exportKey、getParamsの非表示値、JSON文字列を返す特殊部品をadapter内で対応付け、契約へそのまま漏らさない。

復元setParamsで入力イベントを発火させてmetadata更新を繰り返さない。UIがvalidate済みでもHostが再検証する。未知のfieldIdは拒否し、method引数へ透過転送しない。非表示欄の値を保存することと引数へ渡すことを区別し、全値をkwargs化しない。確定成功でも非表示値を保持する必要があれば、正規化したactive値とその非表示値からなる全体DraftValuesをmetadata.draftに残す。下書きの変更表示はactive値の差分で決める。SQL／script等のstringはstringのままで、JSON parseを全欄へ一律適用しない。構造化欄だけが定義したschemaでJSONを解釈する。

UI向けには定義全体を渡さず、`schemaVersion, connectorId, actionId, definitionVersion, fields` だけへ投影する。fields内の表示・入力型・default・制約・visibleWhen・pickerが対象で、pythonのmodule／class／method／keywordを含めない。UI部品のexportKeyはfieldIdへのadapter対応であり、Python keywordの指定権限を持たせない。

#### 定義の収集時検査

005-04へ渡す検査案は、JSON構造検査と次の意味検査を両方満たすこと。JSON Schemaだけで検査できない対応関係を残さない。

| 検査ID | 収集時に拒否する定義 | 期待結果 |
| --- | --- | --- |
| D03-01 | 同じconnectorId／actionId／definitionVersionの重複、fieldId重複 | あいまいな登録を作らず、収集失敗 |
| D03-02 | argumentsが未知fieldIdを参照、keyword重複、input欄の引数対応が欠落 | 正しい対応を定義側で直す。名前の一致から推測しない |
| D03-03 | 型・nullable・範囲に合わないdefault、空enum／重複enum、不明な構造化型 | 初期表示の前に失敗。defaultを補正して採用しない |
| D03-04 | visibleWhenの未知参照・循環・比較値型違い | 収集失敗。制御欄の正規化値と同じ型の定数だけ比較する |
| D03-05 | path以外のpicker、未知picker種別、未登録のmodule／class／instance対応 | 収集失敗。外部由来定義の動的import／任意OS操作へしない |
| D03-06 | 同じconnectorのaction間でmodule／class／instanceが不一致、実シグネチャとkeywordが不一致 | 003／004へ差を返す。複数の初期化方法を生成しない |

fieldsは処理へ渡す入力欄だけとし、表示上のラベル・説明はlabelKey／descriptionKeyで持つ。処理へ渡さない制御専用の入力欄が必要になった場合は、用途と引数除外の規則を個別に拡張するまで登録しない。visibleWhenが参照する制御欄の入力不正はその欄の検証NGとし、残りの欄を都合よく有効化して確定しない。

`python.result=none` の場合はmetadataのcommitted.outputBindingをnullとする。displayのときだけHost発行の結果名を必須にする。Noneを返すアクションでもdisplay指定なら通常代入し、戻り値がNoneだから自動的にnoneへ切り替えることはしない。

### E. Python生成・値・結果・例外

### J. 2026-10-25の共通フォーム構造・定義検査・正規化の詳細案

#### J.1 定義の共通形と型ごとの制約

ActionDefinitionは§Dの必須欄を維持し、現在のschemaVersion候補は1、definitionVersionは正の安全整数、ID・labelKeyは空でないstringとする案。未知schemaVersionを受理しない。fieldIdはaction内で一意、表示名とPython keywordを別に保持する。fields／argumentsの配列順は保持し、入力欄のないactionも表せる。各objectの未知キー・型に適用できない制約を拒否し、defaultの注入やキー削除で定義不正を補正しない。

全fieldで `fieldId, labelKey, valueType, required, nullable, inactivePolicy` を明示する。required／nullableはboolean、inactivePolicyは§Dの `preserveDraftOmitArgument` 固定。descriptionKey・default・visibleWhen・pickerと型別制約は任意。defaultはDraftValueで、unsetを許さず、同じ正規化・制約で検査する。requiredとnullableは独立で、requiredかつnullableの明示nullは値として成立する。

| valueType | 制約欄の具体案 | 確定時に受ける値と禁止する暗黙変換 |
| --- | --- | --- |
| string | minLength／maxLength（非負安全整数、両方あればmin≦max） | textをそのままliteral stringへ。空白・Unicode・改行を保持し、JSON parseやtrimをしない |
| path | minLength／maxLength、picker | 空でないtextをliteral stringへ。存在・権限の事前検査や絶対path化を共通処理へ加えない。file／directoryのダイアログ条件は登録済み定義から取得 |
| boolean | 型以外の数値・文字列制約なし | json booleanだけ。textのfalse、数値0／1をbooleanへ変換しない |
| integer | minimumDecimal／maximumDecimal（正規形decimal string） | textの符号付き十進整数、またはjsonの安全整数。任意精度で範囲比較・正規化し、安全域ならliteral、それ以外はinteger decimalへ。JSON numberを経由しない |
| number | minimum／maximum（有限JSON数、整数なら安全域） | textのJSON数値構文またはjson number。boolを拒否。有限で、整数に評価される値は安全整数域を必須にする。負の0は0へ正規化し、特殊な符号保持契約を増やさない |
| enum | options：空でない順序付き `{value,labelKey}` 配列 | json primitiveを型付きで照合する。optionsのvalueは同じ型の非null string／boolean／有限number（整数なら安全整数域）、同値重複禁止。nullはnullableで扱い、文字列0と数値0を同一視しない |
| array／object | valueSchema：同梱の構造化値schema | jsonのarray／objectだけ。JSON文字列を共通処理でparseしない。全入れ子はJsonValueを満たし、巨大整数wrapperを任意位置へ展開しない |
| variable | 任意の登録済み型参照は004との照合対象 | textのASCII単一識別子だけ。対応Python版の予約語・None／True／False・式を拒否し、BoundValue.variableへ。存在・実型はカーネル実行に委ねる |

全型で `json.value=null` はnullableの場合だけliteral nullへ、それ以外は型不正。型別で受けないDraftValueの形は意味検証NGとし、string欄のjson string等を黙って別形へ補正しない。committedをフォームへ戻すadapterは、field型に従いstring／path／variableと数値入力をtext、boolean／enum／構造化値をjsonへ対応付ける。これはsourceの逆解析ではない。

integerのtextは `+`・先頭ゼロを許して正規化するが、空文字・符号だけ・空白・小数・指数表記を拒否する。numberのtextはJSON数値の十進・小数・指数構文を最後まで満たすものだけを受ける案で、部分的なparseで末尾文字を捨てない。整数の境界比較を浮動小数へ変換しない。minLength／maxLengthはJSON SchemaのUnicode code point数とし、JavaScriptのUTF-16単位数や通信のUTF-8 bytes上限と分ける。

構造化値のvalueSchemaは2020-12で、root typeをfieldのarray／objectと一致させる。初回の許可語候補は `$ref, $defs, type, properties, required, additionalProperties, items, anyOf, enum, minimum, maximum, minLength, maxLength, minItems, maxItems`。typeは単一のJSON型、refは同梱登録済みID／内部fragmentだけ。未知語・外部取得・任意コードは拒否し、ラベル等の注釈と実値制約を混同しない。必要な追加語は004の実型を受領して検査範囲を明示してから拡張する。任意JSON SchemaをUIから受け付ける機能にはしない。

#### J.2 表示条件・投影・定義検査

visibleWhenは引き続き `{fieldId,equals}` だけとし、参照先はboolean／enumの制御欄に限定する案。equalsはその欄の値型と一致し、enumなら選択肢内、nullならnullableを必要とする。任意JS式・複数文・truthy判定は持たない。

依存graphの循環を収集時に拒否し、制御欄→依存欄の順で表示条件を評価する。同順位はfieldsの定義順を使う。参照先が非表示／未設定なら条件不成立。表示中の制御欄が意味検証NGならその欄をエラーとし、子欄を都合よく有効にして確定しない。非表示の制御欄に残る古い値で孫欄を有効化しない。nullableの明示nullと未設定は別に比較する。

UI向け投影は識別・版とfieldの表示／入力制約だけ。Pythonのmodule・class・instance・method・keywordを渡さない。HostはUIの表示判定・検証結果を信頼せず同じ共通定義から判定し直す。UIのfieldIdをPython keywordの指定権限にせず、正本のargumentsで一対一に対応付ける。現在のfieldsはすべて処理入力欄であり、制御専用欄を追加する場合は除外規則の別設計が必要。

| 検査と具体化 | 収集を失敗にする条件・照合先 |
| --- | --- |
| D03-01／02 | ID・版・fieldId・keywordの重複、未知参照、対応の欠落・多重対応。名前一致から引数対応を推測しない |
| D03-03 | 型に不適用の制約、逆転した範囲、型違い／範囲外default、混在型／重複／空enum、root type不一致のvalueSchema。defaultも意味検証を通す |

#### J.3 Hostでの正規化順序と結果

以下は処理順序の設計であり、実関数や実装済みAPIではない。JSON構造の妥当性とaction固有の意味を分ける。

1. 同梱定義と版・登録先・D03の検査結果を確認する。値から呼出し先を選ばない。
2. §Cの優先順で全体値を選ぶ。draftが非nullならその全体だけ、次はcommitted、両方nullなら定義defaultで初期状態を作る。committedはBoundValuesの構造・fieldId・版を確認し、field型に従う新しいDraftValuesへ投影してから後段へ渡す。不正な上位値から下位値へ黙ってfallbackしない。
3. DraftValueの構造とfieldId登録を全体で検査する。非表示欄でも不正wrapper・未知fieldIdを透過保存しない。途中textの意味不正と構造不正を分ける。
4. J.2の依存順で表示条件と有効欄を決める。有効欄だけを意味検証し、非表示欄はrequired・default再適用・引数生成の対象にしない。
5. 有効欄の欠落／unsetはrequiredならエラー、任意なら省略。明示null・空string・False・0を欠落へ変換しない。選び直した未設定へdefaultを再注入しない。
6. 型・範囲を検査してBoundValuesを作る。エラーが1件でもあれば全体NGとし、committedとsourceの新しい編集計画を作らない。保存済みの下書きを保持し、値やstackを含まないfieldErrorsを返す。
7. 成功時にだけ、正本arguments順で有効値を渡す計画と、必要な保持下書きを作る。入力のDraftValues自体は変更しない。Notebook編集と部分失敗の扱いは005-02／002へ渡す。

保持下書きは、存在する非表示欄のDraftValueを元のまま残し、有効欄は型に応じた正規化後のDraftValueへ揃えた全体mapとする。保持すべき非表示キーがなければdraft=nullとし、次回はcommittedから復元する。非表示の明示unsetも勝手に削除しない。committedに存在する任意引数の省略は、復元時にもdefaultで穴埋めしない。アクション変更時の旧値破棄は既存規則のまま。

条件はHost検証後の確定値で比較する。未設定をseparateとせず、省略値raiseなら追加しない。呼出し1回→success代入→errors代入→元bindingの表示の順。0行でも2キーを受け取る。各df・attrsはカーネル内にあり、Hostが結果受信後に代入を起動する方式ではない。

収集時は対象C01／E01／E03・display・enumのseparate・2キー／suffix一意・派生名の識別子妥当性を検査する案。保存・クレンジング等へ透過追加しない。公開APIの辞書キー適合は004／003で確認する。

002にはsource全体の保存・再確定・手編集／Undoを確認する。通常読取へ戻して再確定すれば新sourceから追加代入を除くが、カーネルの過去変数は消さない。途中失敗・前回値残存は通常Pythonのままで、自動rollback・隠れた実行なし。再オープン後も同じbindingから再現できる。success／errorsは行分類で、errors空をHostの実行current判定に使わない。

#### K.5 標準実行の列名→辞書セル／renameセル

通常呼出しの定義だけでは、結果を受けて別セルを作る操作を表せない。**列名だけの取得結果と、明示したセル作成を分ける005案**を[005-02 §13](TASK-005-02.md#connector-handoff-20261030)へ渡す。全列の同名辞書literal専用セル・別renameセル・入力dfの再実行で上書きしないという採用済み要件を維持する。

生成入力は単一df参照、列名と順序、辞書変数名、rename結果変数名。Hostが生成するのは検証した列名literalの辞書と標準rename・全結果列のis_unique検査。出力の任意コードをsourceへコピーしない。変更先同士・未変更列との衝突は、標準実行時に結果df全体で検査し、結果変数の代入前にValueError。入力dfをinplace変更しない。

文字列列名の説明例（未実行、命名は仮）。辞書セルは辞書定義だけ：

```python
rename_columns = {
    "商品コード": "商品コード",
    "数量": "数量",
    "金額": "金額",
}
```

別のrenameセル：

```python
_rename_candidate = df_success.rename(columns=rename_columns)
if not _rename_candidate.columns.is_unique:
    raise ValueError("変更後の列名が重複しています")
df_renamed = _rename_candidate
df_renamed
```

取得の列順・重複を保持し、同一keyを別キーへ自動改名しない。同名入力の一律拒否・自動採番を追加せず、辞書とname-based renameの対応を004と照合する。非string・tuple／MultiIndexをstrへ変換する契約も採用せず、型付き列名の対応範囲を002／004で確認する。stringの例だけで全列取得要件を縮小しない。
