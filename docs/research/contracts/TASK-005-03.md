## 値とPython sourceの対応案

以下は共通境界への提案。metadataの正式キーやJSON Schemaではない。部品から届いた値をそのままPython式へ連結せず、アクション定義にある入力の種類に従ってHostで検証・変換する。

| 入力の種類 | sourceへの対応候補 | 区別するもの・残る条件 |
| --- | --- | --- |
| 文字列・SQL・scriptの本文 | 引用符・改行・バックスラッシュを保つPython文字列リテラル | 文字列を通常の生成処理でPython式として評価しない。Pythonコネクタがscriptをどう扱うかは個別の判断 |
| path | カーネルから参照できるpath文字列として表現 | Windowsのバックスラッシュも保存。末尾バックスラッシュを持てないraw文字列の機械的利用は避ける候補。HostのURIとカーネルのpathは同一とは限らない |
| bool・数値 | True／False、型と範囲を検証した数値リテラル | Falseと0を未設定にしない。有限値、整数・小数、JavaScriptで精度を失う大きな整数の表現を定義する必要がある |
| 配列・辞書 | 要素・キーの型を検証し、Pythonのlist／dictとして表現 | NodeFormの特殊部品が返すJSON文字列と、既に構造化された値を区別する。全ての文字列をJSONとして解釈しない |
| null／任意値の欠落 | 明示Noneと、引数自体を省略する場合を区別 | 欠落時の初期値をUI・Host・Pythonで一致させる。空文字も別の値として扱う |
| 入力表などの変数参照 | 例のdf_salesなら、引用符なしの単一変数名として生成 | UI／metadataには参照名だけを保持。実オブジェクトはカーネル内。存在・型の最終確認はPython側で行い、Hostから裏側で評価しない |
| 出力の変数名 | 代入が必要なら検証した単一名を使う | 自動名・利用者指定・衝突・既存値の上書きは未決。新しいフォーム欄の追加は今回決めない |
| 非表示・未知の項目 | 有効なアクション入力だけを引数へ渡す候補 | 非表示値を保存するか、実行引数へ渡すかは別。未知キーを任意のメソッド／引数へ転送しない |

単一変数名は、最初はASCIIの英字・数字・アンダースコアかつ先頭数字不可、Python予約語不可とする案を比較対象にする。Unicode識別子を認める案もあり、正式な制限ではない。df.ilocや関数呼出し等の式を認めるかも未決だが、最小案では単一名に限定する。自由なPythonは標準コード欄で書ける既存方針を維持する。

呼出し先のmodule・class・methodはアクション定義との対応で管理する候補。利用者のフォーム値をそのままimport名や呼出し先へ使わない。JSONのtrue／false／nullとPythonのTrue／False／Noneは異なるため、JSON文字列をPython sourceとして直接使う方式にしない。変換器は今回実装していない。

## 未設定・下書き・確定の整理

- 選択時：以前のアクションの下書き・確定値を破棄し、新アクションの初期値と未設定状態からsourceを生成する既存方針を継承する。
- 編集中：下書きだけを更新し、現在の確定済みsourceを維持する。
- 確定NG：入力欄へ検証結果を返し、確定済み設定とsourceを変更しない。セル更新の原子性・失敗応答はTASK-005-02／TASK-002-02で定義する。
- 確定OK：型・必須条件を満たした値と対象アクションからHostがsourceを生成する。生成だけではPythonを実行しない。

| 未設定のsource案 | 標準実行したとき | 判断点 |
| --- | --- | --- |
| U1：説明コメント＋明示的なValueError（推奨候補） | 未設定と分かるPythonエラー。標準の「すべて実行」もそのセルで停止する | 設定漏れを明確にできるが、後続セルも止まる影響がある |
| U2：説明コメントのみ | 何も処理せず、標準実行は次へ進む | 未設定でもエラーが出ない。業務処理を実行した成功と区別する必要がある |
| U3：有効な初期値だけで業務呼出しを生成 | 手動の標準実行時に初期値で実処理する | 必須path・SQL・project等の妥当な値を保証できないアクションがある。仮のIDや空欄を有効とみなさない |

U1／U2について利用者へ動作を確認中。回答前に採用しない。U3を全アクションへ一律適用しない。未設定のsource生成と、標準実行を拡張側で禁止する仕組みは別であり、独自の実行制御は追加しない。

## 7コネクタ・16候補との対応

IDと対象アクションの根拠は[004の候補表](../connectors/TASK-004-01.md)。全件採否未定。旧戻り値やschemaを新契約に固定しない。TASK-004-02は未着手のままで、ここでは設計に必要な境界だけを対応付ける。

| コネクタ・候補ID | 境界で確認する入力・出力 | 個別設計へ残す事項 |
| --- | --- | --- |
| CSV：C01／C02 | 読取はpath等の値、書込は表の参照と出力先。DataFrame／旧完了文字列 | encoding・区切り・行位置・空表・schema、書込既定値と上書き |
| Excel：E01／E02／E03 | path・sheet・range等の値、書込の表参照。DataFrame／旧完了文字列 | 空欄とactive sheet、範囲内行位置、置換・追記、型とファイルロック |
| DuckDB：D01／D02／D03／D04 | DB・SQLまたはSQLファイルの値、表作成の入力表参照。表／旧作成情報 | DB・表の作成と置換、SELECT以外の戻り値、SQLが伴う入出力 |
| BigQuery：B01／B02／B03 | project・SQL・出力先等、ロードする表参照。表／None／旧Job情報 | 認証・課金・書込mode、時刻・schema変換。認証情報はフォーム設定や生成sourceへ含めない |
| Python：P01 | 通常Python切替と別の処理として何を提供するか、script／入力／戻り値の責務 | 旧env_path・子プロセス・main()・JSON往復を前提にしない。役割の判断が必要 |
| Data Integration：I01／I02 | 表参照、RENAME path、conditions等の構造化値。処理した表 | 型・attrs・rename／filterの細部と空条件、非表示値・schema欄の意味 |
| Shell：S01 | BAT path、引数を文字列／配列のどちらで扱うか。旧stdout等の表 | Windows・cwd・引用符・cp932・終了コード・取消／時間制限。単なるPython文字列エスケープではShell引数の扱いまで保証しない |

ファイルを読む処理は、初期化時ではなく処理セルの実行ごとに読み直す既存要件を維持する。再実行によるCSV上書き・Excel追記・DB置換・BigQueryジョブ・BATの副作用を一律に冪等とみなさない。
