## 1. 今回重要と考えること

- **値を失う前に保持する。** CSVの文字列、Excelで選んだ取得方式の値を保持する。先頭ゼロ、空文字、timezoneなどを先に消すと、後から復元できない。
- **前処理の責務を明確にする。** 読込、前処理、型変換、失敗行の分離、名称変更、保存を区別する。必要な前処理まで省略する、という意味ではない。
- **採用済みの前処理を確実に行う。** 明示型指定列の空文字・空白だけの値を欠損へ揃える。非空文字列の一括trim、NA／NULLの一律欠損化は追加しない。
- **クレンジング処理は残し、Data Integrationへ移管する。** CSV・Excel・BigQuery等の取得元に依存しない処理として、列単位で切替可能、初期は無効とする。読取アクション全体のON／OFFを置く案へ戻さない。
- **業務の加工を隠さない。** 桁区切り・通貨記号の除去、独自日付の修正等が必要なら、通常Pythonセルで明示する案。勝手な推測で正常値に変えない。
- **既存のエコシステムを使う。** pandas、openpyxl、DuckDB、Google公式SDK、Python標準機能を優先する。独自の型推論器・SQL解析器・実行エンジンを増やさない。ただし標準APIの成功と、採用した仕様への適合は別に確認する。
- **正常データの意味を揃える。** 停止／欠損化／行分離で、同じ設定・同じ取得方式の共通正常行の値・型・列順が変わらないようにする。
- **後続処理に勝手な加工を持ち込まない。** CSV／Excel書込は明示選択したdfを保存する。errorsを選んでも、読取時の型変換を再度適用しない。
- **副作用を動作として説明する。** ファイル・シート・DB表の置換、SQL更新、外部ジョブ、BAT実行は区別する。失敗しても全変更が取り消されると保証しない。

前処理の位置の例：
`取得値を保持 → 型指定列だけ空欄前処理 → 明示型変換 → 選んだ失敗時処理 → 別セルの加工／名称変更 → 明示選択したdfを保存`。
errorsは作業用の変換後データから逆算せず、前処理前の値から作る。

### Q01｜相対パスは何を基準にするか

### Q02｜Data Integrationで名称変更後の同名をどう防ぐか

- 対象：Data Integrationの名称変更。別セルの辞書と標準Pythonのdf.renameを使う。
