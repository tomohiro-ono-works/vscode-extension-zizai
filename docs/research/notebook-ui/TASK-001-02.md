### 実行確認時に重点を見る箇所

- comboのopenMenuはinputのたびdocumentへpointerdownを追加し、outsideを上書きする一方、closeでは最後のoutsideだけを解除する（JS 170〜216行）。ブラウザで3回入力→destroyを実行し、pointerdownリスナーが2件残ることを再現した。動的検査は不合格。今回の判定調査では上流を修正していない。
- Shadow DOMによる隔離を選ぶ場合、rootにはShadowRootそのものではなく内側のElementが必要。browse-requestはbubbles:trueだがcomposed指定なしなので、shadow境界外のdocumentで拾えると仮定しない。rootでの受信等を評価する。Shadow DOM採用は未決定。
- 同じDOM環境でスクリプトを再評価するとwindow.NodeFormと連番が再初期化され得る。読込を一度にする管理や、フォーム／セル／Notebook対応を評価する。IDだけを本拡張の正式なセル識別にしない。

## Notebookでの配置条件

[TASK-001-01の結果](TASK-001-01-statusbar.md) はセル下部のテキスト項目と標準QuickPick。NodeFormはHTMLのrootとDOMイベントを必要とするため、この表示面へフォームを埋め込むことはできない。

先行する [HTMLフォーム常設調査](TASK-001-01.md) でも、標準Rendererは出力表示用であり、実行前の常設フォーム用スロットにはならない。editorInsetsによるNotebook内フォームも実機成立は未確認。**NodeFormを選ぶことではフォームの配置問題は解決しない。**

Notebook出力にサンプルを表示できたとしても、実行前から常設の合格にはしない。独立HTML／Webviewなら部品単体の評価候補にはなるが、サイドパネル等への製品方針変更をこの調査で確定しない。フォームを必要とする後続設計は、この未決事項を明示して進める必要がある。

## 取得・同期・更新経路の候補

利用許諾は確認済み。製品へ取り込む場合は表示面の決定と不合格箇所への対応後に次を評価する。まだvendorディレクトリや依存管理方式は作らない。

1. commit固定の上流JS／CSSを原本として管理し、URL・commit・ファイルhash・LICENSEと実際の許諾記録を追跡する。mainの無条件追従はしない。
2. VS CodeテーマCSSとHost接続アダプターを上流原本から分離する。上流に必要な修正は差分と更新方法を記録し、生成物への直接patchで済ませない。
3. 上流更新時は差分・ライセンス・テスト結果を照合してから同期する。package.jsonがない候補をnpmパッケージとして導入できるとは仮定しない。

- 実施環境：クラウドLinux、Node 24.19.0、Python 3.12.14、Playwright 1.62.0、Chromium 154.0.8037.57。上流commitは変更なし。初回のNode実行後、取得方法による末尾改行の追加を除去し、7ファイルすべてが上流blob hashと一致した状態で再確認した。
- 上流テスト：`node test/node-form.test.js` が終了コード0、`node-form tests passed`。
- ブラウザ評価：[実行スクリプトと再現手順](../../../tests/nodeform-reuse/README.md)、[実行JSON](evidence/TASK-001-02-browser.json) を参照。6件中5件合格・1件不合格で終了コード1。サンプルの描画時JS例外はなし。
- 合格範囲：値の往復・必須検証・初期値不変・編集通知・フォーム間分離・visible_if・模擬browse結果とキャンセル・破棄後の遅延結果無視。
- 不合格：comboへ繰り返し入力するとdocumentのpointerdownが3件登録され、destroy後も2件残る。前述のopenMenu／closeの登録解除の対応と整合する。採用時に修正と再確認が必要。

- ローカルfile://表示が環境ポリシーで禁止されるため、取得済みソースを空ページへ注入して確認した。これをCSP・実URL読込・IDE適合の検証には数えない。ファイル選択はDOMイベント模擬であり、OSダイアログは未実施。

## 結論と再開条件

**再利用候補としては残せるが、そのままの全面採用は行わない。** 利用許諾は確認済みで、単体機能の多くは実行確認できた。comboの不合格への対応、テーマ調整、HTMLフォームの配置条件とIDE適合確認が残るため、TASK-001-02は保留を維持する。

再開に必要なのは、部品を評価するHTML表示面と、製品が求めるフォーム配置条件の整理。その面でローカル読込・CSP・テーマ・実OSファイル選択・複数セルの共存を確認し、comboを修正・再確認する。部品単体の合格をNotebook内常設の合格にはしない。サイドパネル等への方針変更は確定しておらず、新たな実機テストは今回は依頼しない。
