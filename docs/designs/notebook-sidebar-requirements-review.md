# サイドバーの選択・保存・復元と要件対応

基準は[全体設計](01全体設計.md)、[Notebook UI設計](02NotebookUI設計.md)、[承認済みサイドバー設計](../features/notebook-sidebar.md)。既存の12項目と画面・状態・通知の対応を確認し、UIが決める動作とHost／正式契約から受け取る部分を分ける。新しいwire名・metadataキー・復旧APIは定義しない。

「フェーズ1」は全体設計の実装順序案にある「セル選択・metadata：選択・保存・復元」を指す作業上の切り分け。初回リリース全体やTASK-001-03〜05の完了条件を縮小するものではない。確定・生成コード・実行対応の要件も保持し、必要な工程で照合する。

## 12項目と画面・状態の対応

| 項目 | 表示・操作・状態の対応 | UI側の判断と境界 | 既存の確認ケース |
| --- | --- | --- | --- |
| ① 処理選択 | セル側の1つのメニューから通常Pythonまたは各コネクタの処理を選ぶ。「設定」でサイドバーの対象を指定 | メニュー構成は2026-10-25の利用者選択で確定。通常PythonとPythonコネクタの処理を区別する。正確なラベルは実装・実機と照合。Hostが選択を反映 | U02、U10、M01、M04 |
| ② フォーム位置 | 1つのサイドバーにNotebook・現在のセル位置・処理を表示。単なるセルクリックでは対象変更なし | 承認済み。同名Notebookは相対位置も表示し、表示番号をIDにしない。対象対応・生存確認はHost | U01、U02、U21〜U30、M01、M08、M09 |
| ③ 常時展開 | 対象フォーム内の入力・エラー・状態・確定を独自に折りたたまない | 承認済み。サイドバー全体の開閉と標準のコード／出力折りたたみはIDEへ委ねる | U03、M10、M11 |
| ④ コード表示 | Notebook標準のsourceと出力を利用。設定を開くだけではsource・出力・実行状態を変更しない | 承認済み。UIはPython生成・実行・標準結果の代替を持たない | U02、K01、M01、M10 |
| ⑤ 通常Python | 通常Pythonでは詳細フォームとアクション専用欄を表示しない | 承認済み。通常PythonとPythonコネクタの別を、共通選択の確定時にも確認する | U04、M02 |
| ⑥ 下書きの破棄 | A→B→Aの表示切替では各下書きを保持。同じセルで処理変更なら旧下書きを破棄 | 承認済み。切替前にHostとの保存整合を確認。失敗時は旧対象と入力を維持し、切替成功を表示しない | U07〜U10、K01、K04、M03、M04 |
| ⑦ 確定値の破棄 | 同じセルの処理変更時は旧確定値も破棄し、新初期状態を表示 | 承認済み。Hostが設定・sourceを反映。必須未入力時の生成範囲はコネクタ／Python境界へ確認し、UIが仮コードを作らない | U10、K01-05、M04 |
| ⑧ 入力エラー | 確定時に必須・範囲等を検証し、該当項目直下へ表示。NGでは下書きを残し確定値・source不変 | 承認済み。正式な定義とvalidatorが必要。更新失敗は項目検証と区別し、対象と失敗をフォーム上部に表示 | U12〜U17、K02、M05 |
| ⑨ 未更新 | source反映後はフォーム上部に表示。「下書き」と共存でき、現在設定の実行成功が証明された場合だけ解除 | 表示動作は承認済み。実行対応・再オープン後の観測方式は002／005が担当。成功だけから推測しない | U16〜U19、K06、M05、M10 |
| ⑩ 下書き保存 | 入力はHostがセルmetadataへ保存し、sourceは確定まで変更しない。通常保存した下書きは再オープン後の明示選択で復元 | 承認済み。Host確認済みの状態とディスクへの標準保存を区別。Viewキャッシュを正本にしない | U06〜U11、U27、U28、K01、K05、M03、M06、M07 |
| ⑪ 手動コード編集 | sourceを編集してもフォームへ逆同期しない。次の明示確定でフォーム値から再生成 | 承認済み。生成・source更新はHost。元Pythonコードの一時退避は閉鎖後の復元を保証しない | U20、K06、M12 |
| ⑫ 初期化セル | 共通選択・「設定」・詳細フォームの対象外。標準source・実行・出力を利用 | 承認済み。識別はHostの正式な状態を使い、セル位置や見た目から推測しない | U05、M02 |

この対応は設計レビューであり、U／K／Mの実行結果ではない。①の利用者判断は[決定記録](../decisions/2026-10-22-notebook-sidebar.md)を参照。正式契約・実装境界の未確定部分を残したまま、03全体や製品の完成を宣言しない。

## 既存の未決事項との照合

| 論点 | 判断済みのUI動作 | 残る確認と責務 |
| --- | --- | --- |
| 未入力時 | 未確定の入力を下書きとして扱い、確定の検証NGは項目直下へ表示。勝手に確定・実行しない | 個別初期値・必須判定と、選択直後に生成できるsourceの範囲は004／005・002へ確認。空欄から実行可能コードを生成できるとはしない |
| 下書き補助表示 | 入力変更時に「下書き」を表示し、「未更新」と区別する | 正式な下書き確認とsnapshotの対応を005／002へ確認。Hostへの反映とNotebookのディスク保存を混同しない |
| 通知方法 | 入力検証は項目直下、更新失敗は対象と失敗をフォーム上部、対象喪失は選び直し、別Notebookでは編集不可 | 正式なエラー分類・未知状態・部分更新停止／復旧の対応を005／002へ確認。成功をUIで推測しない |
| 選択の具体形 | 通常Pythonと各コネクタの処理を1つのメニューにまとめ、設定対象は「設定」で明示する | 利用者の今回の選択を根拠とし、正確なラベル・標準UIでの表示を後続と照合。試作の動作実績を製品検証の合格にはしない |
| 再表示・クローズ | 開いたNotebookのView再表示はHostから復元。Notebookを閉じた後は対象を自動復帰しない | 最後のタブとDocument寿命を別に扱う正式Host境界を確認。Undo後の参照・旧要求を取り違えない |

## 保存と復元で分けて観測する対象

| 観測対象 | 更新／復元の契機 | 誤って同一視しないもの |
| --- | --- | --- |
| UI入力 | ユーザーの入力。切替・応答待ち中にも失敗時の値を保持する | Hostが受理した値・ディスクに保存した値 |
| Hostが対象セルへ反映した下書き | 対象と要求の有効性を確認した下書き処理 | 確定値・生成source・標準保存完了 |
| Notebookの通常保存済み内容 | 標準の保存／再読込 | Viewキャッシュ・未送信入力・閉鎖前の一時退避 |
| 確定値とsource | 正式な確定成功／処理変更をHostが反映 | 下書き編集や表示対象変更だけでは更新しない |
| 現在の対象 | Hostが生存・帰属を確認した明示選択 | 表示番号・同名Notebook・複製セル・失効した旧要求 |

具体的な前後値と観測点は[K01の選択・保存・復元詳細](../../tests/integration/sidebar-selection-state-cases.md)を正本とし、UI単体の注入成功と実Notebook保存を分けて確認する。初期化・通常Python・見出し・フォーカスの実画面は[M手順](../../tests/manual/TASK-001-sidebar.md)へ渡す。
