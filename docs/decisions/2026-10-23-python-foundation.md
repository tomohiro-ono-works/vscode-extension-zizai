## 2026-10-30：保存先フォームのファイル名は名前だけとする

003のフェーズ1照合中に、保存先フォームのファイル名欄へ絶対path等を入れると、別欄の保存先folderが使われない場合があることを説明し、「名前だけを受け付ける」か「pathも許可する」かを質問した。利用者の回答は **「名前だけを受け付ける（推奨）」**。

- 適用対象はCSV／Excel保存先のfile_name欄。folder欄と分離し、フォルダ成分・絶対path・drive指定を名前として扱わない。黙ってbasenameを抽出したりtrimして通したりしない。
- 名前欄の入力不備として検証する責務は004／005の個別定義・生成側へ渡す。通常Pythonの保存APIはoutput_pathへ完成したpath文字列を受け取るため、この引数を名前だけへ制限しない。coreのpath helperや新しい実行処理は追加しない。
- 本回答は名前欄の動作の判断。005のkernelPathJoin種別・schema版、002の生成・保存設計全体、製品実装／UI適合の承認・完了には広げない。[003の照合回答](../research/python-import/TASK-003-02.md#contract-response-20261030)とIssue #21へ対応付ける。

## 2026-11-01：未完了の定義と入力検証・Python実行の分担

統合先チャットで、未設定セルの動作をまとめて確認した際の利用者回答：

> 処理コードを生成しない
> でOKです。

ファイル存在確認に関する同じ回答：

> 別でファイルが存在しない場合のチェックは、アプリ側でのバリデーションは不要です。
> Pythonが行うべきだと思うので

続けて「アプリは入力内容を検証し、実環境に依存する確認はPythonで行う」という下表の分担と、未完了／実行失敗の区別、値保持・既存source保持を提示した。既存設計資料への反映確認に対し、利用者は **「OKです。」** と回答した。これは今回提示した共通方針への承認であり、未提示の制限値・個別API・製品実装の承認ではない。

### 承認された共通方針

| 検証パターン | 担当 | 対象例 |
| --- | --- | --- |
| 必須項目の未入力 | アプリ | 必須のファイル名・入力変数名が未入力 |
| 入力の型・選択肢・範囲 | アプリ | 整数欄への文字列、不正な選択値、項目定義の範囲外の行番号 |
| 項目同士の組合せ | アプリ | 開始行が見出し行以前、必要な関連項目が未入力 |
| 入力形式 | アプリ | 単一変数名の構文、名前だけの欄へのフォルダ指定 |
| ファイル・フォルダの実状態 | Python | 存在、読書き権限、破損、文字コードによる読取可否 |
| カーネル内のデータ | Python | 参照変数の存在、実際の型、列の存在 |
| 外部サービス・実処理 | Python | 認証、接続、SQLの有効性、保存・実行の成否 |

アプリの入力検証はUIの表示とHostの入力検査の責務に対応する。既存の「UIで検証してもHostが再検証する」境界を維持し、ファイルI/O・カーネル評価・外部接続を確定のために実行しない。Python APIを手書きで利用する場合に必要な引数検証もPython側に残す。

- **設定未完了**は、必須入力が不足している、またはアプリで判定できる入力不正がある状態。既存の選択・確定の契機に従い、入力検証が成立するまで新しい処理コードを生成しない。未設定用のraise・passや独自実行制御を追加しない。
- **設定完了・実行失敗**は、入力検証は成立したが、ファイル不在等でPythonが失敗した状態。設定未完了と区別し、標準の例外表示を使う。ファイルが実在することをコード生成の前提にしない。
- `0`・`False`を未入力にしない。省略・空文字・nullは項目定義に従って区別し、黙って補完・trimしない。任意欄の省略や、許可された空文字・nullまで一律に未完了にしない。
- 下書き編集中・確定NG時は下書きと既存の確定済みsourceを保持する。実行失敗を理由にsourceを消去したり、成功扱い・未更新解除にしたりしない。処理切替の具体的な編集・部分適用時の回復保証は既存の002／005の条件を維持する。

### 先行判断・検討案との関係

005での先行回答「ValueErrorで設定不足を明示し、そのセルで停止する（推奨）」と説明用raise例は履歴として保持する。後の質問や資料の新しさだけで上書きせず、今回の直接選択と共通方針への明示承認を根拠として、上記対象の現行方針を更新する。旧C03-04等の未設定用ValueError／Run All停止は、今後の受入期待値へ転用しない。設定完了後の実処理でPythonが通常のValueError等を送出することは、この変更の対象ではない。

今回の記録・文書整合はマージまで。製品コード・schema・validator・生成器は変更せず、実装・実機・UI・CI・配布の合格を認定しない。正式キー／版・入力上限／移行・N05の出典と接続・D3の非破壊保証・D4の実行対応・個別BigQuery／Shellの未決は別に残す。進捗・承認経緯は[005-03 #38](https://github.com/tomohiro-ono-works/vscode-extension-zizai/issues/38)と[005-02 #37](https://github.com/tomohiro-ono-works/vscode-extension-zizai/issues/37)を正本とする。
