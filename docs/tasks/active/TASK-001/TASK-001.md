# TASK-001: Notebook UIの成立性と初回共通操作

## 基本情報

- ID：TASK-001
- 状態：未着手
- 主担当領域：Notebook UI
- 関係領域：VS Code 拡張機能本体、共通契約、開発運用・プロジェクト管理
- 主工程・関連工程：調査、設計、実行、単体テスト、検証
- 更新日：2026-10-19

## Goal（ゴール）

通常コードセル内の選択・フォーム操作が、標準sourceと出力を保ちながら利用できる。

## Scope（スコープ）

- 対象・正本候補：apps/gui/ のUI正本とNotebook内統合。NodeFormは外部由来の再利用候補で、取得元・版・ライセンス・更新経路の確認前はコピーしない。
- 対象外：Python生成、セル編集、Python実行、独自結果表示。
- 正本・更新経路：配置責務はアーキテクチャで確認済み。具体的なファイル・API・生成／同期手順は設計Subtaskで確認して記録する。配置名だけで編集権限を確定しない。
- 今回の編集範囲：本TaskとTask索引のMarkdown整理のみ。以下の実行・テスト等は将来の作業定義であり、今回は実施しない。

## Constraints（制約）

- 全体設計を正本、Notebook UI設計を詳細、アーキテクチャを責務の基準とする。未決定の方式・API・版をTask作成で確定しない。
- 既存Jupyterカーネル、標準セル実行・Run All・結果・Python例外表示を使う。独自実行基盤とDataFrame同期を追加しない。
- 初回範囲に限定する。別アプリの仕様・Task・承認・コネクタ一覧を採用済みと扱わない。
- 標準Notebookの出力・metadataにはデータが残り得る。認証情報・実データを共有資料・テスト証跡へ残さない。
- 調査結果が設計の成立を否定した場合は事実を記録し、影響する後続作業を止める。独立した調査は続行可能。

## Acceptance Criteria（完了条件）

- [ ] 通常Python・処理・初期化のセル別UI、常時展開・テーマ・入力エラーを両IDEで確認できる。
- [ ] アクション切替の旧設定破棄、下書き保存復元と確定時だけのsource適用がHost連携と一致する。

- [ ] 上記ゴールを満たすことを、必要なSubtaskの結果・対象版・環境と照合できる。
- [ ] 全ての必須Subtaskの完了条件を満たし、不具合修正後の関連再確認も記録されている。
- [ ] デスクトップ必須確認とクラウドの確認を区別し、未実施・不合格を合格にしていない。
- [ ] 未決事項・未実施・残る影響と後続Taskへの受け渡しを明記している。必須確認未達のままTask完了にしない。
