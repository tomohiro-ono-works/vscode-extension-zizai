## Goal（ゴール）

## Scope（スコープ）

- 対象・正本候補：開発手順、マニフェスト・依存宣言・ロック、.vscode/、scripts/、.github/、tests/integration/・e2e/・manual/ と配布手順。各領域の単体テスト正本は当該Taskに属する。
- 対象外：実際の外部公開・出荷承認の代行、初回の自動互換性チェック、未確定の次回機能実装。
- 正本・更新経路：配置責務はアーキテクチャで確認済み。具体的なファイル・API・生成／同期手順は設計Subtaskで確認して記録する。配置名だけで編集権限を確定しない。
- 当初の編集範囲：本TaskとTask索引のMarkdown整理のみ。
- 今回の追加範囲：継続依頼を受けたTASK-006-01の環境棚卸し・配布候補の設計準備。docs/research/development/TASK-006-01.mdと環境証跡evidence/TASK-006-01-environment.json、本Task、Task索引、README.md、docs/development.mdの6ファイルを編集する。READMEと開発手順は試作用F5設定に関する古い案内の事実修正のみ。製品コード・manifest・lock・起動設定は作成／変更せず、依存導入・製品ビルド・CI・パッケージ化・実機確認は行わない。

## Constraints（制約）

- 全体設計を正本、Notebook UI設計を詳細、アーキテクチャを責務の基準とする。未決定の方式・API・版をTask作成で確定しない。
- 既存Jupyterカーネル、標準セル実行・Run All・結果・Python例外表示を使う。独自実行基盤とDataFrame同期を追加しない。
- 初回範囲に限定する。別アプリの仕様・Task・承認・コネクタ一覧を採用済みと扱わない。
- 標準Notebookの出力・metadataにはデータが残り得る。認証情報・実データを共有資料・テスト証跡へ残さない。
- 調査結果が設計の成立を否定した場合は事実を記録し、影響する後続作業を止める。独立した調査は続行可能。

## Acceptance Criteria（完了条件）

- [ ] 対象版・依存・コマンドを追跡できるビルド／CIと、両IDEで初回共通機能・全採用アクションを通した結果がある。
- [ ] 拡張とPythonライブラリを同梱したZIPを任意の場所へ展開し、手動導入後に選択カーネルで実行できる。
- [ ] 拡張とPythonライブラリの個別版、初回に互換性チェックを行わない条件と残るリスクを導入手順・出荷判断材料に記録する。

- [ ] 上記ゴールを満たすことを、必要なSubtaskの結果・対象版・環境と照合できる。
- [ ] 全ての必須Subtaskの完了条件を満たし、不具合修正後の関連再確認も記録されている。
- [ ] デスクトップ必須確認とクラウドの確認を区別し、未実施・不合格を合格にしていない。
- [ ] 未決事項・未実施・残る影響と後続Taskへの受け渡しを明記している。必須確認未達のままTask完了にしない。
