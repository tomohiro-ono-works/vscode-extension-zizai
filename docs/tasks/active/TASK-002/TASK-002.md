# TASK-002: Extension HostのNotebook管理

## 基本情報

- ID：TASK-002
- 状態：進行中
- 主担当領域：VS Code 拡張機能本体
- 関係領域：Notebook UI、共通契約、コネクタ、開発運用・プロジェクト管理
- 主工程・関連工程：調査、設計、実行、単体テスト、検証
- 更新日：2026-10-21

## Goal（ゴール）

フォーム設定からPython sourceを生成し、metadata・初期化セル・一時状態を標準Notebook編集と整合して管理できる。

## Scope（スコープ）

- 対象・正本候補：apps/extension/ のHost正本とNotebook編集API統合。契約定義の正本はTASK-005に集約する。
- 対象外：Python実行、業務データ処理、独自Run All、カーネル管理。
- 正本・更新経路：配置責務はアーキテクチャで確認済み。具体的なファイル・API・生成／同期手順は設計Subtaskで確認して記録する。配置名だけで編集権限を確定しない。
- 当初の編集範囲：本TaskとTask索引のMarkdown整理のみ。以下の実行・テスト等は将来の作業定義であり、この整理では実施しない。
- 2026-10-21の継続範囲：TASK-005-01に続くTASK-002-01の静的API調査として、固定版の公開型・実装、セル識別・編集・保存・実行観測の制約を照合する。正本はdocs/research/notebook-host/TASK-002-01.md、証跡は同配下evidence/。本Task・索引を更新する。利用者の意向に沿って調査用research/task-005-01-boundariesを継続し、001の実機検証用ブランチは変更しない。製品・正式契約・検証用拡張・起動設定・現行仕様・他Subtaskには着手しない。Kiroは今回の対象外を継承する。

## Constraints（制約）

- 全体設計を正本、Notebook UI設計を詳細、アーキテクチャを責務の基準とする。未決定の方式・API・版をTask作成で確定しない。
- 既存Jupyterカーネル、標準セル実行・Run All・結果・Python例外表示を使う。独自実行基盤とDataFrame同期を追加しない。
- 初回範囲に限定する。別アプリの仕様・Task・承認・コネクタ一覧を採用済みと扱わない。
- 標準Notebookの出力・metadataにはデータが残り得る。認証情報・実データを共有資料・テスト証跡へ残さない。
- 調査結果が設計の成立を否定した場合は事実を記録し、影響する後続作業を止める。独立した調査は続行可能。

## Acceptance Criteria（完了条件）

- [ ] 選択即時反映、下書きsource不変、確定NG時の値保持、保存復元とNotebook間分離を確認できる。
- [ ] 初期化セルの先頭生成・再利用とセル移動／複製／削除／Undo時の整合、元コード一時退避を確認できる。
- [ ] 生成Pythonは標準実行だけで評価され、未更新は現在の設定による成功時のみ解除される。

- [ ] 上記ゴールを満たすことを、必要なSubtaskの結果・対象版・環境と照合できる。
- [ ] 全ての必須Subtaskの完了条件を満たし、不具合修正後の関連再確認も記録されている。
- [ ] デスクトップ必須確認とクラウドの確認を区別し、未実施・不合格を合格にしていない。
- [ ] 未決事項・未実施・残る影響と後続Taskへの受け渡しを明記している。必須確認未達のままTask完了にしない。
