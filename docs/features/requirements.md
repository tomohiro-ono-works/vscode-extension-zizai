# ZizAI 要件仕様書

## TASK-028：Windowsの画面入力と前後の待機

「待機に関しては、画面操作のアクションにそれぞれ前後で秒単位で設定できるようにして」を受け、共通フォームのクリック・文字入力・キー入力に「操作前の待機（秒）」と「操作後の待機（秒）」を設ける。どちらも0以上の整数で初期値は0。生成コードの実行時に前待機、操作、後待機の順で処理する。ダブルクリックの前後を待機し、2回のクリックの間には設定した待機を入れない。入力送信が失敗したときは後待機せず、エラーを返す。

- クリックは左・右、シングル・ダブル、現在位置・X/Y座標指定を選ぶ。文字入力はカーソル位置への入力を既定とし、全選択して置換も選べる。キー入力は単一キーとCtrl・Shift・Altの組み合わせを指定する。
- ローカルWindowsカーネルで生成コードを明示実行すると、操作時点のカーソル位置やフォーカスを対象にWindows標準APIで入力する。文字入力ではクリップボードを使用せず、入力内容を結果に含めない。結果は入力をWindowsに送信できたことを表す。実アプリでの動作確認は[TASK-028](https://github.com/tomohiro-ono-works/vscode-extension-zizai/issues/116)で管理する。
- クリックフォームの「3秒後に座標取得」を押して取得したい位置へカーソルを動かすと、3秒後にX・Yが入り、「座標指定」に切り替わる。取得した値は手修正できる。取得は位置を読み取るだけで、クリックを実行しない。クリック前後の待機秒数は変更しない。取得中にアクションを切り替えると取り消し、取得に失敗したときは直前の設定を保持する。

## TASK-027：Windowsのファイル操作

「windowsのコネクタに進みましょうか」を受けた初回実装。旧版のファイル操作4件を[共通フォーム](https://github.com/tomohiro-ono-works/vscode-extension-zizai/issues/82)へ接続する。[TASK-027](https://github.com/tomohiro-ono-works/vscode-extension-zizai/issues/114)で状態を管理する。

| 操作 | 主な入力 | 結果 |
| --- | --- | --- |
| ファイル名検索 | 検索フォルダー、サブフォルダー検索、ファイル名・拡張子の正規表現、検索時間の目安 | `df` にフォルダーとファイル名 |
| ファイル内の文字列検索 | ファイル名検索の条件、本文の正規表現、一致行の前後行数 | `df` にファイル名、1始まりの行番号、一致行と前後の抜粋 |
| Markdown作成 | 保存先、ファイル名、本文、新規作成・追記・上書き | `result` に保存結果 |
| ファイル名の変更・移動 | 対象ファイル、移動先と新しいファイル名のうち少なくとも一方、ファイルがない場合のスキップ指定 | `result` に移動結果 |

- ファイル名の正規表現は拡張子を除いた名前に適用する。本文はUTF-8（BOM含む）、CP932、Shift_JISに対応する。フォルダー内のリンク先は検索しない。検索時間の既定は120秒で、ファイルの境界で時間を確認する。途中で止めた場合は警告と部分結果を返す。
- Markdownは拡張子の省略時に `.md` を補い、UTF-8で保存する。新規作成が既定。追記・上書きは書き込み方法で明示する。移動先に同名ファイルがある場合はエラーとする。
- 正本は `connectors/windows/windows_connector.py` と同じフォルダーのYAML。外部共通フォルダーへ配置し、通常の `import windows_connector` を使うコードを生成する。ファイル操作は生成したコードをセルで実行した時点で行う。

## TASK-016：Python実行

[Issue #90](https://github.com/tomohiro-ono-works/vscode-extension-zizai/issues/90)の「Python実行（ファイル）」は、引数なしの `main()` を持つ `.py` を `参照…` から選ぶか、絶対パスを入力する。出力変数の初期値は `result`。利用者の指示によりフォームの環境指定欄を廃止し、生成コードはカーネルと同じPython環境を使う。[TASK-017 #91](https://github.com/tomohiro-ono-works/vscode-extension-zizai/issues/91)

利用者が生成コードを実行すると、通常の `import python_connector` を使い、`sys.executable` で起動した別プロセスで `main()` を1回呼ぶ。実行権限は利用者のPythonと同じ。stdout・stderrと戻り値を分け、表・辞書・リストはDataFrameに、スカラー・NoneはPython値に戻す。受け渡しはJSONで行い、表の列は保持する。元のインデックス・型・attrsの完全保持は契約に含めない。一時ファイルは終了後に整理する。既存の生成コードが使う `execute_python` とAPIの `env_path` は互換性のため維持する。

## TASK-021：DataFrameの値加工

[Issue #103](https://github.com/tomohiro-ono-works/vscode-extension-zizai/issues/103)の「データ統合 → 値加工」では、表の上のプルダウンから対象列、処理分類、操作を選ぶ。

- 文字列は、完全一致の置換、部分置換、別列との結合、区切り文字と1始まりの位置による取り出し、正規表現による抽出、前後の空白除去、大小文字変換を提供する。文字列として処理し、NULLを保持する。区切った位置がない場合や正規表現に一致しない場合の結果はNULL。正規表現はグループ番号を指定でき、0は一致全体。
- NULL処理は、指定値をNULLにするか、NULLを指定値で補完する。指定値は文字列・数値・真偽値から選ぶ。
- 数値は四則演算、丸め、絶対値を提供する。四則演算の相手は別列か固定値で指定できる。丸めは小数点以下の桁数を指定する。数値に変換できない値や0による除算は対象列と理由を表示する。
- 加工結果を対象列へ書くか、新しい列にするかを選べる。変更は設定順に先頭30行のコピーへ適用して表示する。サンプルを加工できない設定は変更一覧に追加せず、直前の結果を保持する。
- 生成コードを利用者が実行すると全行を加工した別のDataFrameを返す。元表と行インデックスを保持し、列名を重複させない。

## TASK-020：DataFrameの列操作

[Issue #101](https://github.com/tomohiro-ono-works/vscode-extension-zizai/issues/101)で、既存のNotebookフォームに「データ統合 → 列操作」を追加する。現在のカーネルにあるDataFrameを選び、先頭30行を表で表示する。列数が多い場合は横スクロールする。

- 列見出しの右クリックで削除または型変換、ダブルクリックでその場で名前変更、ドラッグ＆ドロップで列移動ができる。型変換の設定と確定はプレビュー表の上で行う。「選択した列だけ残す」では複数列を指定できる。変更一覧に実行順を表示し、最後の変更を取り消せる。
- 削除予定の列は、見出しとデータを灰色でプレビューに残す。右クリックの「元に戻す」はその列の削除予定だけを取り消す。生成コードの実行時に削除予定の列を取り除く。
- 各列名の左に現在の型を表すアイコン（文字列 `ABC`、整数 `123`、小数 `1.2`、日付はカレンダー）を置く。アイコンのクリックで変換先を選び、サンプルで成功するとアイコンと表に反映する。
- 設定を追加するたび、先頭30行のコピーに同じPython関数を適用して結果を表示する。文字列、整数、小数、日付を指定できる。日付は時刻を切り落とす。サンプルの型変換に失敗したときは対象列を表示し、直前のプレビューと設定を保持する。
- 「コード生成」で設定済み操作を通常のPythonコードにする。利用者が実行すると全行を加工し、別のDataFrameを返す。出力変数の初期値は `processed_df`。次のステップはその変数を入力にできる。元データと行インデックスを保持し、既存の列説明を引き継ぐ。
- 列名は1段で、表示名に重複がない表を扱う。操作による名前の重複、存在しない対象列、全行の実行時に型変換できない値はPythonのエラーで知らせる。

## TASK-015：RENAMEリストで列名変更

[Issue #89](https://github.com/tomohiro-ono-works/vscode-extension-zizai/issues/89)の列名変更は、既存のDataFrameとUTF-8のRENAME CSV（BOM可）を入力とし、別のDataFrameを返す。フォームのRENAMEリスト欄では、`参照…` で `.csv` を選ぶか、絶対パスを入力する。出力変数の初期値は `renamed_df`。生成時はファイルを読み込まない。RENAMEリストの見出しは `origin_name` と `replaced_name` または `new_name`。旧版の日本語見出しも使える。任意の `description` と `ziz_datatype`（例 `INT64`）で説明・明示の型変換を指定できる。

変更前の空白・改行削除、全角英数字の半角化、半角記号のアンダースコア化、変更後の日本語を含む列の除外は、フォームで選んだ項目だけ適用する。初期値はすべてオフ。入力表の内容と、出力内の型指定のない列の値・型を保持する。変更による列名衝突や矛盾する定義はエラーとする。出力の列名・説明・型は `attrs["ziz_schema"]` に記録する。

## TASK-014：BigQueryフォーム

[Issue #88](https://github.com/tomohiro-ono-works/vscode-extension-zizai/issues/88)のSQLファイル実行とデータロードを外部共通フォルダーの `bigquery_connector.py` と `bigquery_definition.yaml` で提供する。出力変数の初期値は `result`。コード生成時はファイル読込・認証・接続を行わない。実行時はフォームで指定したプロジェクトと、Python環境のApplication Default Credentialsを使用する。

- SQL実行では `参照…` でGoogleSQLの `.sql` ファイルを選ぶか、絶対パスを入力する。文字コードはUTF-8またはShift_JIS。任意の出力スキーマは `origin_name`、`new_name` などを使う既存のZizAI形式。クエリ結果はDataFrame、結果表のないジョブは完了情報を返す。既存Notebookから呼び出すPythonの `execute_sql` は継続する。[TASK-017 #91](https://github.com/tomohiro-ono-works/vscode-extension-zizai/issues/91)
- データロードはDataFrameを指定されたプロジェクト・データセット・テーブルへ渡す。初期設定は「新規／空テーブル」（`WRITE_EMPTY`）。「追記」または「置換」は明示して選択する。省略可能なロード用スキーマはBigQueryのフィールド定義JSON（`name`、`type`、必要に応じて `mode` や `fields`）。
- 実サービスの確認で実行するSQLは `SELECT 1` に限定する。架空データによるロードは通信を代替して検証する。

## TASK-013：DuckDBフォーム

[Issue #86](https://github.com/tomohiro-ono-works/vscode-extension-zizai/issues/86)のDBファイル作成は、外部共通フォルダーの `duckdb_connector.py` と `duckdb_definition.yaml` を使う。保存先フォルダーを選び、ファイル名を指定する。初期ファイル名は `sample.duckdb`。拡張子省略時は `.duckdb` を補い、入力されたフォルダーがなければPythonの実行時に作成する。同じDBファイルを指定した場合は開いて閉じ、既存テーブルを保持する。DBのパス・ファイル名・拡張子を除いた名前・処理時刻を1行のDataFrameで返す。3アクションとも出力変数の初期値は `result`。依存は `duckdb` extraから導入する。

「SQL実行（ファイル）」では、既存DBとSQLファイルをそれぞれ `参照…` から選ぶか、絶対パスを入力する。SQLファイルの文字コードはUTF-8が初期値で、Shift_JIS／CP932も選べる。生成コードを実行すると、Pythonが選択したSQLを読み込み、指定DB内で実行する。SQLからの外部ファイルへのアクセスは接続設定で無効化し、設定をロックする。入力するSQLは信頼済みのものを前提とし、結果はDataFrameとして受け取る。既存Notebookから呼び出すPythonの `execute_sql` は継続する。[TASK-017 #91](https://github.com/tomohiro-ono-works/vscode-extension-zizai/issues/91)

テーブル作成はNotebookの表データを指定した既存DBに保存する。フォームのテーブル名初期値は `table1`、作成モード初期値は「新規作成」。同名テーブルがあれば実行時にエラーとし、既存データを保持する。「置換」を選んだ場合は、生成コードが `replace=True` を渡して指定テーブルを置換する。新規作成・置換の結果は、DBパス、テーブル名、行数、処理時刻を含むDataFrameで返す。

## TASK-012：Excelフォームとコネクタ

[Issue #85](https://github.com/tomohiro-ono-works/vscode-extension-zizai/issues/85)の3アクションを、外部共通フォルダーの `excel_connector.py` と隣接する `excel_definition.yaml` で提供する。対象形式はローカルの `.xlsx`。フォームは通常の `import excel_connector` と関数呼び出しを生成する。パスは `/` 区切りとし、計算やファイル操作は生成コードの実行時に行う。

- 通常読込と範囲読込では、入力ファイル欄の `参照…` から `.xlsx` を選択するか、絶対パスを入力する。通常読込はシート全体から1始まりのヘッダー行とデータ開始行を指定する。範囲読込は `A2:B5` などを入力し、範囲内の1始まりで行を指定する。フォームの初期値はシート名 `シート1`、ヘッダー行 `1`、データ開始行 `2`。通常読込の分割行数は `50000`。読み込みの結果と書き出しの入力はDataFrameで渡せる。
- 書き出しは `output.xlsx`・`シート1` を初期値とし、書き込みモードの初期選択は `create_or_replace`（対象シートを置換）、もう一方は `create_or_insert`（既存シート末尾へヘッダーなしで追記）。フォームは選択されたモードを生成コードへ明示する。ないブック・シートは作成し、別シートを維持する。書き出しに失敗した場合は元のブックを残す。データ内の文字列は文字列として書き、他シートの既存の式は保持する。マクロや一部図形などExcel固有機能の完全な保持は対象外。
- 対象日付・型の共通処理には既存の表変換を使う。Excelのライブラリは別の `excel` extraで導入する。[pandasのExcel依存](https://pandas.pydata.org/docs/getting_started/install#excel-files)のopenpyxl 3.1.5と、[openpyxlが案内するXML保護](https://openpyxl.readthedocs.io/en/stable/#security)のdefusedxml 0.7.1を使用する。

### CSV・Excel共通の行プレビュー

CSV・Excelの通常読み込みで、入力ファイル欄の `行を確認` から先頭30行・最大40列を表示する。表はノートブックの出力幅を使い、横スクロール中も左端の行番号を固定する。行番号の右クリックメニューでヘッダー行とデータ開始行を選び、`確定` でフォームと生成コードに反映する。CSVの文字コード・区切り文字またはExcelのシートはプレビュー内で変更でき、`キャンセル` は元の入力と生成結果を保持する。CSVの空行で読み込みと行番号がずれうる場合は、フォームでの直接入力を案内する。
