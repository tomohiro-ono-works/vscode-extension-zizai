# ZizAI 要件仕様書

更新日：2026-11-08。状態：**新方式の要件案**。記録整理：[TASK-008 / #76](https://github.com/tomohiro-ono-works/vscode-extension-zizai/issues/76)。

本書を、旧設計撤去後の製品要件を整理する正本とする。確定した前提は継続するが、利用者の新方式の例をそのまま実装詳細の承認とは扱わない。未決事項を含むため、製品全体の仕様確定・実装着手・受入完了を意味しない。

## 1. 目的と対象

VS CodeのJupyter Notebookで、コネクタ・アクション・引数を選択／編集し、通常のPython処理につなげる。独立した大きな設定フォームではなく、Notebookのコードを中心とする簡単な操作を目指す。

対象は次の3区分。通常のNotebook編集・保存・Python実行には既存のVS Code／Jupyterを利用する。

| 区分 | 担当するもの | 担当・境界 |
| --- | --- | --- |
| Pythonで実装 | コネクタ／アクションの業務処理。必要に応じたマジックの受付・設定解釈・生成との接続 | コネクタ／アクションはVS Codeから独立。マジック用の接続処理と業務処理は分ける案で、具体的な構成は未決 |
| スニペットで実現 | `@ziz`などから最初のセル雛形を入力する入口 | スニペットの作成・登録は利用者担当。拡張側の候補表示や定義読込とは別 |
| VS Code拡張で実装 | セル内の選択支援、候補と対象文字列の対応、パス選択の接続、必要なNotebook編集 | 新方式の開発対象。UIの実現API・マジック実行後の受渡しは未決 |

スニペット登録は通常のJSON定義を利用する想定。これは利用者の雛形登録であり、後述の動的な候補選択・階層定義・プログラム生成をスニペットだけで構築するという意味ではない。

### 操作イメージ

利用者提示の表記をそのまま残す。次の2例は**UI／設定表記の説明用**であり、そのままPythonとして実行可能なコードや採用済みの保存構文ではない。

1. `@ziz`で最初の雛形を入力する。

```text
%%ziz.connector.action.selector
connector.name        = [C]"" # コネクタ
connector.action.name = [A]"" # アクション
```

2. 選択表示から、例えば`csv`と`export`を選ぶ。

```text
%%ziz.connector.action.selector
connector.name        = [P]"csv"
connector.action.name = [P]"export"
```

3. 標準のセル実行で選択用マジックを実行し、設定入力用のコードを提示する。

```text
%%ziz.connector.action.setting
parameta1 = [P]""
parameta2 = [P]""
```

4. 設定後に設定用マジックを実行し、Pythonプログラムを生成する。そのプログラムは通常のNotebookコードとして編集・実行する。

例の`parameta1`／`parameta2`は仮名。マジック名、設定項目名、`csv`／`export`の公開APIへの対応も、正式な定義で決定する。生成が業務処理の実行も兼ねるかどうかは未決であり、この例だけで自動実行を承認したことにはしない。

## 5. 今回復活させない旧仕様

- サイドバーフォーム、旧フォーム専用の下書き／確定同期、フォーム用metadata・通信契約一式を新方式の前提にしない。
- 独自の実行エンジン・カーネル・Run All・Node.jsとPython間のDataFrame同期は導入しない。既存のNotebook／Jupyterを利用する方針を維持する。
- 初期化セルの自動管理は復活させない。辞書／renameセルの自動作成の要否は、旧設計から推測して新方式へ追加しない。
- Excelの行選択モーダルは復活させない。処理ロジックはPythonコネクタ／アクションへ移管する方針だが、利用者から未共有の具体的なロジックを捏造しない。

## 7. 品質・検証の方針

文字列・パスの入力を安全に扱い、対象外セルや利用者ファイルを変更しない。機密情報をログへ記録しない。通常利用で起きる可能性が相応にあり、利用・データ・セキュリティへ大きく影響する部分を優先する。実装前に低頻度の例外を網羅しない。

新方式で確認が必要な中心は、候補選択と対象値の反映、通常の段階遷移、生成されたPythonの編集・実行である。具体的な期待結果はU01〜U06の判断に合わせて定める。本書の作成だけで、これらの試験が済んだとは扱わない。

エージェントの操作は[CLI/APIと合意範囲のPlaywright](../development.md#allowed-test-operations)のみ。LLMによる直接GUI操作を使わない。
