# ZizAI 要件仕様書

更新日：2026-11-09。状態：**新方式の要件案**。記録整理：[TASK-008 / #76](https://github.com/tomohiro-ono-works/vscode-extension-zizai/issues/76)。

本書を、旧設計撤去後の製品要件を整理する正本とする。確定した前提は継続するが、利用者の新方式の例をそのまま実装詳細の承認とは扱わない。未決事項を含むため、製品全体の仕様確定・実装着手・受入完了を意味しない。

### 今回の開発範囲

その後の利用者指示「今回は一旦VSCode拡張機能のみ」と、ファイル／フォルダー選択の併合を反映し、[TASK-009 / #77](https://github.com/tomohiro-ono-works/vscode-extension-zizai/issues/77)は拡張の候補選択・パス入力・VSIX化と拡張単体の検証に限定する。Pythonコネクタ／アクション、IPythonマジックの実装・実行接続、プログラム生成、利用者のsnippet作成・登録代行は含めない。以下に記載する全体構想を、今回の完成条件と混同しない。

1タスク・3サブタスクで、まず1項目の候補選択を動かし、パス選択、配布・通常経路確認へ広げる。仕様確認・実装・検証は各作業内で行い、必要な判断を対象部分ごとにまとめて確認する。全詳細設計の先行完了や、低頻度例外の網羅を一律の開始条件にしない。未完了の要件を後続へ移しただけで完了とはしない。

## 1. 目的と対象

VS CodeのJupyter Notebookで、コネクタ・アクション・引数を選択／編集し、通常のPython処理につなげる。独立した大きな設定フォームではなく、Notebookのコードを中心とする簡単な操作を目指す。

対象は次の3区分。通常のNotebook編集・保存・Python実行には既存のVS Code／Jupyterを利用する。

| 区分 | 担当するもの | 担当・境界 |
| --- | --- | --- |
| Pythonで実装 | コネクタ／アクションの業務処理。必要に応じたマジックの受付・設定解釈・生成との接続 | コネクタ／アクションはVS Codeから独立。マジック用の接続処理と業務処理は分ける案で、具体的な構成は未決 |
| スニペットで実現 | `@ziz`などから最初のセル雛形を入力する入口 | スニペットの作成・登録は利用者担当。拡張側の候補表示や定義読込とは別 |
| VS Code拡張で実装 | セル内の選択支援、候補と対象文字列の対応、パス選択の接続、必要なNotebook編集 | 新方式の開発対象。UIの実現API・マジック実行後の受渡しは未決 |

スニペット登録は通常のJSON定義を利用する想定。これは利用者の雛形登録であり、後述の動的な候補選択・階層定義・プログラム生成をスニペットだけで構築するという意味ではない。

### 操作イメージ

利用者提示の表記をそのまま残す。次の2例は**UI／設定表記の説明用**であり、そのままPythonとして実行可能なコードや採用済みの保存構文ではない。

1. `@ziz`で最初の雛形を入力する。

```text
%%ziz.connector.action.selector
connector.name        = [C]"" # コネクタ
connector.action.name = [A]"" # アクション
```

2. 選択表示から、例えば`csv`と`export`を選ぶ。

```text
%%ziz.connector.action.selector
connector.name        = [P]"csv"
connector.action.name = [P]"export"
```

3. 標準のセル実行で選択用マジックを実行し、設定入力用のコードを提示する。

```text
%%ziz.connector.action.setting
parameta1 = [P]""
parameta2 = [P]""
```

4. 設定後に設定用マジックを実行し、Pythonプログラムを生成する。そのプログラムは通常のNotebookコードとして編集・実行する。

例の`parameta1`／`parameta2`は仮名。マジック名、設定項目名、`csv`／`export`の公開APIへの対応も、正式な定義で決定する。生成が業務処理の実行も兼ねるかどうかは未決であり、この例だけで自動実行を承認したことにはしない。

### 選択UIの試行承認

利用者の「試してOkです。」に基づき、P01の最小試作として、文字列の左のInlay Hint `[C]`からVS Code標準の候補一覧を開く方式を試行した。Windowsの既定リンク操作ではCtrl＋クリック、候補一覧は画面上部に表示される。`[C]`は保存sourceには含まれない。[観測証跡](../research/notebook-ui/evidence/inline-choice-20261108.json)の1項目の結果であり、他環境・親子候補・新方式全体の受入や、最終的な操作方法の採用までを承認済みとは扱わない。

操作体験後のS10により、最終形の希望は「選択表示へのマウスオーバーで候補を表示し、クリックで確定」と明確になった。Ctrl＋クリックの試行結果は履歴として保持し、この最終形を満たしたとは扱わない。公開APIのホバー内に候補リンクを置く案を次に検討するが、色専用パレットと同じ見た目・任意のドロップダウンを提供できると確約しない。利用者が操作中の試作は勝手に切り替えない。

S11の位置指定に対する最小試作は、対象文字列へTextEditorDecorationの`[C]`を表示し、HoverProviderで同じ文字列の範囲に候補を結び付ける。ホバー内の候補をクリックすると値を反映する。今回のWindows実画面では初回・選び直しともに`[C]`のすぐ上に表示され、修飾キーなしで反映・保存できた。[試作証跡](../research/notebook-ui/evidence/hover-choice-20261108.json)を参照する。上下の配置はVS Codeが画面条件から決めるため、常に下を優先する設定や他の画面条件まで確認済みとはしない。画面上部のQuickPickと旧Ctrl＋クリックの案内は新試作から外す。これは1項目の結果であり、#78全体の完了ではない。

その後の利用者操作で、候補へポインターを動かす途中で消える問題と、選び直しの失敗が報告された。VS Code1.145.2で、連続した通常速度の移動中に消えることを再現した。前述の成功は高速に移動する自動操作の限定結果であり、通常操作の安定性を満たしていない。R02の確認では、候補へ連続してマウスを移動し、途中で消えずクリックできること、保存等の別操作を挟まず選び直せることを含める。選び直しの原因は未確定で、第一の問題と同じ原因と断定しない。

利用者承認による専用Insidersでの比較では、マウス移動中の消失は再現せず、選び直しは別途失敗した。古い版のメニューが残る拡張側の不具合を修正し、確定後に閉じ、次のホバーで現在の状態から開く。[修正後の比較](../research/notebook-ui/evidence/hover-insiders-20261108.json)では連続移動・クリック確定・保存を挟まない選び直しが通過した。1.145.2の制限、正式対応版の未決、利用者による再評価は引き続き区別する。

### パス入力支援（#79）

`%%ziz.connector.action.setting`の`file_path`／`folder_path`を、同梱定義（初回はJSON、YAML承認後はYAML）の`kind: "file"`／`kind: "folder"`で識別する例を実装した。値の左の`[P]`へのホバーから標準選択ダイアログへ接続し、初回入力・選び直し・キャンセルに対応する。取消時は既存値を保持する。選択したファイルの内容は読まず、独自の実在・権限検査やPython実行は追加しない。

S12により、ローカルfile URIの絶対パスを、二重引用符の文字列として対象箇所だけへ反映する規約を採用した。相対パスへの変換や実行時の基準位置の推測はしない。名前・マジックは入力支援の例で、Python APIやアクション採用を決めた意味ではない。[検証範囲](../research/notebook-ui/evidence/path-choice-20261108.json)はInsidersの標準簡易ダイアログでの6通常操作に限り、OSネイティブダイアログ・Remote／WSLを確認済みとは扱わない。

### YAML定義と親子候補（#78、2026-11-09承認）

利用者の「定義ファイルは、yamlにしようか」と、配置案・親変更時の子の保持／消去への「OKです」に基づき、入力支援の定義はYAMLとする。Notebookが属するworkspace folderの `.vscode/zizai-definitions.yaml` を読み、保存後の変更を反映する。利用者snippetのJSONとは別で、Python処理・次セル生成の定義は含めない。

親をメニューで選び直した際、変更先でも有効な子の値は保持し、無効な子だけ空文字へ戻す。親子の変更は1回のUndoで戻せる単位とする。手入力しただけでは他項目を書き換えない。

実装判断：`version: 1`、`magics[マジック名].fields[項目名]`を入口とし、固定候補は`choices`、依存候補は`dependsOn`と`choicesByValue[親の値]`で定義する。依存は同一セル内で解決する。パスは既存の`kind: file`／`folder`を継続する。外部定義なしは同梱例を使用、外部定義ありは全体を置換し、混在マージしない。不正な定義は通知してそのworkspaceの支援を停止し、Notebook本文を保持する。YAMLはデータのみを解釈し、コード・コマンド・外部参照は実行しない。

### 試作VSIXの導入準備（#80）

実装済みの候補1項目とパス選択を内部プレビューVSIXへ梱包する。正本は`apps/extension`、生成手順と入力例は同階層README、作業状態・受入条件は[Issue #80](https://github.com/tomohiro-ono-works/vscode-extension-zizai/issues/80)で管理する。公式vsceの固定版とlockfileを用い、実行時依存・検証Notebook・ログを配布物へ含めない。Marketplace公開・正式対応版の採用は含まない。

専用1.146.0-insiderへVSIXをCLI導入し、開発用パス指定なしの起動を確認する。候補／パスの通常操作、保存・Undo／Redo、対象外セル保持を確認するが、確認中に一度発生したパスのホバー消失は原因未確定として残す。この0.0.1時点の確認では外部定義・親子候補は未実装だった。その後のYAML対応は上記#78節に区別して記録し、当時の検証結果を遡って変更しない。ホバーの未解決を残したまま#78・#80全体を完了扱いしない。対応版・配布の未決U08も維持する。

## 5. 今回復活させない旧仕様

- サイドバーフォーム、旧フォーム専用の下書き／確定同期、フォーム用metadata・通信契約一式を新方式の前提にしない。
- 独自の実行エンジン・カーネル・Run All・Node.jsとPython間のDataFrame同期は導入しない。既存のNotebook／Jupyterを利用する方針を維持する。

- Excelの行選択モーダルは復活させない。処理ロジックはPythonコネクタ／アクションへ移管する方針だが、利用者から未共有の具体的なロジックを捏造しない。

## 7. 品質・検証の方針

文字列・パスの入力を安全に扱い、対象外セルや利用者ファイルを変更しない。機密情報をログへ記録しない。通常利用で起きる可能性が相応にあり、利用・データ・セキュリティへ大きく影響する部分を優先する。実装前に低頻度の例外を網羅しない。

新方式で確認が必要な中心は、候補選択と対象値の反映、通常の段階遷移、生成されたPythonの編集・実行である。具体的な期待結果はU01〜U06の判断に合わせて定める。本書の作成だけで、これらの試験が済んだとは扱わない。

エージェントの操作は[CLI/APIと合意範囲のPlaywright](../development.md#allowed-test-operations)のみ。LLMによる直接GUI操作を使わない。
